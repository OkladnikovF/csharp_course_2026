## Задание 1. Фоновые уведомления

Когда пользователь успешно оформляет заказ, маркетплейс должен отправить ему Email-чек и Push-уведомление в мобильное приложение. Эти действия не должны блокировать поток, отдающий HTTP-ответ клиенту, и должны выполняться параллельно, чтобы не заставлять пользователя ждать.

## Задание 4. Асинхронный пул соединений с БД

Во время Черной Пятницы тысячи запросов одновременно обращаются к базе данных. Создавать новое соединение на каждый запрос — непозволительная роскошь: установка TCP-соединения, аутентификация и аллокация ресурсов занимают десятки миллисекунд. Поэтому в реальных системах используется **пул соединений**: ограниченное количество соединений создаётся заранее и переиспользуется запросами.

Ваша задача — реализовать **потокобезопасный асинхронный пул соединений**, который:

- Хранит фиксированное количество «соединений».
- Позволяет асинхронно занять соединение. Если все заняты — вызывающий **асинхронно ждёт** освобождения, не блокируя поток.
- Позволяет вернуть соединение в пул.
- Обнаруживает «сломанные» соединения и заменяет их на новые.
- Поддерживает отмену ожидания через `CancellationToken`.
- Корректно освобождает ресурсы при `Dispose`.

### 1. Симуляция соединения

Создайте класс, имитирующий соединение с базой данных:

```csharp
public sealed class SimulatedDbConnection : IDisposable
{
    public int Id { get; }
    public bool IsBroken { get; private set; }

    public SimulatedDbConnection(int id) => Id = id;

    /// <summary>
    /// Симулирует выполнение запроса. Задержка 50–150 мс.
    /// Если соединение сломано — бросает InvalidOperationException.
    /// </summary>
    public async Task<string> ExecuteQueryAsync(string query, CancellationToken ct = default)
    {
        if (IsBroken)
            throw new InvalidOperationException($"Connection {Id} is broken.");

        await Task.Delay(Random.Shared.Next(50, 150), ct);
        return $"Result of '{query}' on connection {Id}";
    }

    /// <summary>
    /// Симулирует поломку соединения (например, обрыв сети).
    /// </summary>
    public void Break() => IsBroken = true;

    public void Dispose() { /* в реальности здесь закрытие сокета */ }
}
```

### 3. Требования к логике

#### Хранение соединений

- Внутри пула должна быть **потокобезопасная** коллекция свободных соединений (например, `ConcurrentQueue<SimulatedDbConnection>`).
- При создании пула сразу создайте `maxSize` соединений и поместите их в очередь свободных.

#### Логика `AcquireAsync`

1. Если в очереди свободных соединений есть хотя бы одно — немедленно извлечь его и вернуть.
2. Если свободных нет — создать `TaskCompletionSource<SimulatedDbConnection>`, добавить его в **очередь ожидающих** и вернуть его `Task`.
3. Ожидание должно учитывать **три** условия завершения:
    - Соединение освободилось → `TaskCompletionSource` завершается успешно.
    - `CancellationToken` отменён → `TaskCompletionSource` завершается с `OperationCanceledException`. Ожидающий **удаляется из очереди**.
    - Прошло `acquireTimeout` → `TaskCompletionSource` завершается с `TimeoutException`. Ожидающий **удаляется из очереди**.
4. После успешного получения соединения, если оно оказалось сломанным (`IsBroken == true`), пул должен **создать новое** соединение и вернуть его вместо сломанного. Сломанное соединение должно быть вызвано `Dispose()`.

#### Логика `Release`

1. Если пул уже удалён (`Dispose` вызван) — бросить `ObjectDisposedException`.
2. Если соединение сломано (`IsBroken == true`) — вызвать `Dispose()` на нём, создать **новое** соединение с тем же или новым `Id` и поместить его в очередь свободных.
3. Если соединение здорово — поместить его в очередь свободных.
4. После добавления соединения в очередь свободных, если в очереди ожидающих есть «ждущие» — нужно **передать** соединение первому ожидающему, а не просто класть в очередь. Это гарантирует, что ожидающий получит соединение, а не «конкурирует» с другими вызовами `AcquireAsync`.

#### Логика `Dispose`

1. Все соединения в очереди свободных должны быть вызваны `Dispose()`.
2. Все ожидающие в очереди `TaskCompletionSource` должны получить `ObjectDisposedException`.
3. Повторные вызовы `AcquireAsync` после `Dispose` должны сразу бросать `ObjectDisposedException`.
4. Повторный вызов `Dispose` не должен бросать исключение (идемпотентность).
